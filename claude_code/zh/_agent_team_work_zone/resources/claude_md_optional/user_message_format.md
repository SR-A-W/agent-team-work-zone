## 给用户的消息（格式）

- 不要用消息轰炸用户：小进展不报或少报，能合并就合并。
- 由成员或子代理的汇报触发、发给用户的消息，以 **队内简报：** 开头，后面只跟一两句极简短的描述。
- 需要用户了解或裁定的内容，以一级标题 `# To Be Read By User` 开头：单独占一行、用 Markdown 一级标题来写，保证它加粗、大字号、醒目；不要只写成普通的加粗文字。标题下第一行是状态行（写作 `**状态：需裁定**` 这样的加粗形式），从下面四种里选一种：
  - **需裁定**：有事要用户决定，用户不回就推进不下去；
  - **进展**：汇报，不需要用户做什么；
  - **更正**：推翻或修正先前给用户的说法——写明原来说的是什么、现在改成什么；
  - **静默轮**：定时巡视，没有新情况。
- 状态行写的是这条消息处于什么状态，不是内容摘要，让用户一眼判断要不要现在读、要不要回。
- 成员的心跳（idle_notification）和"收到""开始做了"这类确认一律不转给用户。几路结果陆续到达时，先各发一句简报，全部到齐后再出一份完整汇报。
- 不用颜色；强调只用 Markdown 本身。
